# VDPポート参照先の分離実験

拡張BASICの対応対象は、V9968が内蔵VDPとして構成された環境に限定します。
外付けV9968カートリッジは対応対象外とし、この実験は参考検証として保存します。通常のビルド・起動への組み込みや、本体への外付け対応の追加は行いません。

拡張BASICとは独立した、openMSX専用の検証です。通常の拡張BASIC ROMはロードしません。
0006h・0007hだけを変更した場合に、参照型の処理と標準BIOSの処理がどちらのVDPへアクセスするかを比べます。
`-RomHook` を指定すると、別途生成する実験ROMへ0047hの呼び出しを渡す検証を行います。

## 実行

既存の `tools/setup.ps1` で準備したエミュレータとBIOS、z88dk、Node.jsを使います。
別途、openMSXの拡張定義 `HRA_V9968.xml` を配置しておいてください。
プロジェクトのルートからPowerShellで実行します。

```powershell
.\experiments\vdp-port-shadow\run.ps1
```

ドキュメントフォルダー内の `openMSX/share/extensions/HRA_V9968.xml` を優先して探します。
見つからない場合はプロジェクト内とProgram Files内も探します。別の場所にある場合は明示できます。

```powershell
.\experiments\vdp-port-shadow\run.ps1 -ExtensionFile 'D:\path\to\HRA_V9968.xml'
```

専用エミュレータを画面なしで起動し、検証後に終了します。
機種定義、拡張定義のコピー、アセンブル結果、`result.json` は実行ごとに `.local/vdp-port-shadow/` の別フォルダーへ出力します。
配置済みの拡張定義は内容を変更せずコピーし、専用の検索先から `-machine PortShadow -ext HRA_V9968` で起動します。
機種定義に外付けVDPを直接追加する方式ではありません。起動後にも `list_extensions` で拡張名を検査します。
通常の機種設定、`src/`、`dist/`、既に起動しているエミュレータは変更しません。

## 構成と手順

- ディスクROMなしのMSX2+、Z80、128KB RAM。FS-A1ST / R800での検証とは別です。
- 内蔵V9958は98h～9Bh、外付けV9968は88h～8Ch。
- 外付け側は、配置済みの [HRA_V9968.xml](https://github.com/buppu3/openMSX/blob/d884c4b/share/extensions/HRA_V9968.xml) を拡張として読み込みます。
- 割り込みは内蔵VDPのまま。外付けVDPの割り込みは有効にしません。

1. 0006h・0007hを参照するマシン語で、レジスタR#7への書き込みとS#1のID読み出しを行います。
2. ページ0（0000h～3FFFh）をRAMへコピーし、コピー側の0006h・0007hを両方88hに変更してページ0へ配置します。コピーとスロット切り替えは割り込み禁止中に行います。
3. 同じ参照型の処理を実行します。
4. 標準BIOSの `WRTVDP`（0047h）を実行します。
5. 元のBIOS、スロット、マッパー設定、両VDPのR#7を復元します。

CPUが実行するコピーと書き換えは `probe.asm` にあります。デバッガーからBIOSを書き換えるテストではありません。
ホスト側は検証コードのロード、開始指示、結果の読み取りを担当します。
S#1の出力は `(S#1 AND 3Eh)` で、V9958は4、対象forkのV9968は6です。
ただし外付けV9968は初期状態でV9958互換IDを返すため、ID読み取り時だけR#21のFIDを解除し、直後に元の値へ戻します。復元も検査します。

## 検証する結果

| 操作 | 内蔵VDP | 外付けVDP |
|---|---|---|
| RAMコピー配置前の参照型アクセス | R#7を変更、IDを読み出し | 変更なし |
| RAMコピー配置後の参照型アクセス | 変更なし | R#7を変更、IDを読み出し |
| RAMコピー配置後のWRTVDP | R#7を変更 | 変更なし |

この結果は、0006h・0007hがソフトウェア向けのポート番号情報であり、固定ポートを使う命令を自動的に転送する仕組みではないことを示します。
BIOS全体や標準BASICの外付けVDP対応を実現する実験ではありません。

## WRTVDPを実験ROMへ渡す検証

```powershell
.\experiments\vdp-port-shadow\run.ps1 -RomHook
```

目的は、固定ポートへの直接書き込みを回避し、ROM内の処理から元の呼び出し元へ戻れるかを確認することです。このモードでは標準BASICのVDP命令の停止原因は調査しません。

```text
RAM上のBIOS入口0047h
  → 予約済みRAMの中継処理
  → CALLF（RST 30h）でスロット1の実験ROMへ
  → 0007hを参照してR#7に書き込み、RG7SAVを更新
  → 元のスロットと呼び出し元へ復帰
```

- `wrtvdp-rom.asm`：R#7限定の18バイトの処理。BIOSコードの複製ではありません。
- `rom-hook.asm`：0047hの差し替え、中継、解除、復帰状態の検査。既存のRAMコピー処理を共用します。
- 出力する `wrtvdp-hook.rom` は16KBの実験ROMで、`.local/vdp-port-shadow/` にのみ生成します。
- C=7以外は元のWRTVDPへ渡します。R#6で元の経路へ戻ることも検査します。
- R#7は0007hに従うため外付け側へ、それ以外は元のBIOSのままです。全VDP操作の外付け対応ではありません。

専用MSX2+ / Z80構成とHRA_V9968拡張で、263回のROM呼び出しに成功しています。うち256回は書き込み値を0～255へ順次変更します。
毎回HL・DE・IX・IY・SP・基本スロットの保持を検査し、BASICの配列・文字列、ページ0の内容、マッパーと副スロットの復帰も確認します。
0047hの差し替え解除後に元のBIOSが内蔵側へ書くことを確認し、最後に元のBIOSと両VDPのR#7を復元します。

この段階では他のVDPレジスタの互換処理、他のBIOS入口、BIOS内部アドレスを直接呼ぶ経路は置き換えていません。
`-BasicStatement` とは同時指定できません。

## 標準BASIC命令の別検証

```powershell
.\experiments\vdp-port-shadow\run.ps1 -BasicStatement
```

基本検証と元のBIOSへの復帰を完了した後、再びRAMコピーへ切り替えて `VDP(7)=9` を試します。
現在の構成では、この標準BASIC命令でスロット状態が崩れて停止することを確認しています。
そのため、このオプションは現状エラー終了する停止再現用です。CPUとスロットの状態を `result.json` に記録して、専用エミュレータを終了します。

`WRTVDP` の直接呼び出しが戻ることと、BASICの `VDP` 命令が正常に戻ることは別の検証です。
停止原因の詳細と、標準BASIC・サブROMを含めたRAM上のBIOSとの共存は未解決です。

## BIOS・BASICの32KBコピーとスロット管理情報

```powershell
.\experiments\vdp-port-shadow\run.ps1 -FullShadow -ExpandedSlot0
```

メインROMの所在を示す `FCC1h`（EXPTBL先頭）と `FFF7h`（MAINROM）も変更する独立検証です。
`-RomHook`、`-BasicStatement` とは同時指定できません。

1. コピー前の標準BASIC `VDP` 命令が正常に戻ることを確認します。
2. 未使用のマッパーセグメント4・5に、BIOSとBASICの32KB（0000h～7FFFh）をコピーします。
3. CPUのページ0・1へそのRAMを配置し、0006h・0007hは88h、FCC1h・FFF7hは83h（RAMスロット3-0）にします。
4. コピー内容、VDP参照型アクセス、WRTVDP直接呼び出し、BASICの配列・文字列を検査します。
5. 元のROM、スロット・マッパー、EXPTBL・MAINROM・SLTTBL、VDPのR#7へ復元できることを確認します。
6. 再びRAMコピーへ切り替え、標準BASICの `VDP(7)=9` を実行します。

コピー時だけページ2を作業窓として使います。BASICプログラムを含む元のRAMは隠すだけで、上書きしません。
`-ExpandedSlot0` は専用の機種定義で元のBIOSをスロット0-0へ置く指定です。通常の機種定義は変更しません。
省略すると従来の専用構成と同じ、スロット0が非拡張の状態で試します。

管理情報の変更だけを除いた比較もできます。

```powershell
.\experiments\vdp-port-shadow\run.ps1 -FullShadow -ExpandedSlot0 -KeepMainRom
```

### 確認結果

| 構成 | 32KBコピー・参照アクセス・復元 | コピー後の標準BASIC VDP |
|---|---|---|
| スロット0非拡張、FCC1h/FFF7hを83hへ更新 | 成功 | 戻らない |
| スロット0拡張、FCC1h/FFF7hを83hへ更新 | 成功 | 戻らない |
| スロット0拡張、FCC1h/FFF7hを変更しない | 成功 | 戻らない |

32KBのコピーと管理情報の更新だけでは停止は解消していません。
検証用のSUB-ROM（MSX2PEXT.rom）には、FCC1hのbit7で拡張処理の有無を判断しつつ、基本スロット番号は0を選ぶ経路がありました。
実行記録でも、SUB-ROMの0287h付近でスロット0の副スロットを扱い、RAM中継F38Chから元のメインROMへ切り替わっています。
管理情報の更新だけで全経路がRAMコピーへ向くわけではない、というところまで確認しています。
これを停止の唯一の原因と断定したり、SUB-ROMを追加改変して直したりはしていません。

このため `-FullShadow` は現状、手順5までの成功を表示した後、手順6の未復帰を検出してエラー終了します。
未復帰後の環境復元は主張せず、専用エミュレータを終了します。
`result.json` の `corePass` がコピー・復元検査、`pass` が全体の結果です。`slotTrace` にスロット切り替えの先頭64件を記録します。
完了通知は予約済みRAMへの実際の書き込みを捕捉し、一時的なスロット切り替えでRAMが見えなくなる場合と区別します。
停止時の `failureState` はその時点でCPUから見える値です。FFhが読めても、元のRAM内容がFFhへ書き換わったと断定はできません。

## メモリと制限

- 起動直後の専用構成で未使用のマッパーセグメント4を、16KBのコピー先として使います。`-FullShadow` では4・5の計32KBを使います。汎用的なメモリ確保処理ではありません。
- CPUのページ0と、RAMマッパーのセグメント0は別です。セグメント0へ上書きしません。
- 検証コードと通信領域は、標準BASICの `CLEAR 512,&HBFFF` で予約してから配置します。切り替え処理とスタックはページ0・1の外にあります。
- 各操作後にBASICの整数配列と文字列を確認し、HIMEMが変わらないことを検査します。最後にBASICプログラム本体も比較します。
- BIOSのコピーはポート情報の2バイト以外が元と一致することを検査します。`-RomHook` 中は、追加で0047hのジャンプ先だけが変わることを検査します。復帰後のBIOS・スロット・マッパー設定も比較します。
- 割り込み処理の全面移行、サブROMの移設・改変、上記以外のスロット配置、DOSや他の常駐ソフトとの共存、実機での安全性は対象外です。

このマシン語を別機種や普段使いのセッションへ直接ロードしないでください。
問題が起きた場合も、専用エミュレータを終了すれば元の開発環境には影響しません。
